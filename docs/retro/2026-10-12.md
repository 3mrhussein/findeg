# Agent investigation retro — 2026-10-12

This retro covers the main `/to-spec` session and four read-only subagent investigations: domain rules, business gaps, Storefront, and Dashboard. The agents made 331 tool calls in total. Individual investigations took roughly 5–10 minutes. Results were generally accurate when spot-checked; most avoidable effort came from missing navigation and missing automated checks.

## Findings

### 1. Enforce authorization in server actions

The Dashboard audit found exported server actions that mutate roles and other privileged data without checking a session or permission. Reading the implementation was the only way to find this. The security work is ticket #425.

**Environment improvement:** add a Next.js lint/architecture rule for exported actions in `'use server'` modules, with fixtures proving that an unguarded action fails. Document the approved guard pattern. Narrow permission-code types to the canonical `PermissionCode` type so invalid codes fail at type-check time.

### 2. Detect dead code and unreachable routes

The audits manually checked many files and links. They found about 85 unreachable Dashboard files and about 10 dead routes or endpoints. Several reported bugs came from dead code, making handoff claims unreliable until reachability was checked.

**Environment improvement:** add an unused-file/export check such as Knip with an explicit baseline for existing debt, and a route/link reachability check for local `href` and API `fetch` paths. Run both in CI.

### 3. Give domain agents the complete source map

`docs/agents/domain.md` points agents to the glossary and ADRs, but not to `docs/business/`, `docs/business-domain-map.md`, or `docs/business-domain-schema-report.md`. One agent reconstructed an inventory already documented in the schema report. Business rules and positioning were also missed, leading to incorrect early spec details.

**Environment improvement:** add those documents to the domain-agent wayfinding instructions. State that `GLOSSARY.md` follows the business source docs so positioning stays consistent.

### 4. Make shell guidance zsh-safe

Across the five sessions, unquoted globs such as `--include=*.ts` caused zsh “no matches found” errors, sometimes hidden by a pipeline and mistaken for an empty search. Other calls failed around `=` expansion and zsh’s lack of default word splitting.

**Environment improvement:** add a short AGENTS.md note to quote globs (`--include='*.ts'`) or use `rg -g '*.ts'`, avoid words beginning with `=`, and use arrays or explicit arguments instead of relying on word splitting. Prefer `git grep`/`rg` to broad recursive grep; `git grep` also avoids unrelated `.claude/worktrees` copies.

### 5. Enforce app data-layer boundaries

AGENTS.md says app-side server queries should import `server-only`, but the rule is not mechanically enforced. Audits found query modules missing the import and pages importing backend modules directly instead of using the app data layer.

**Environment improvement:** add lint rules requiring `server-only` at the top of app query modules and preventing app pages/components from importing backend implementation modules directly. Keep enforcement in the Next.js apps; do not put `server-only` in shared packages.

### 6. Document coding standards the review skill can apply

There is no `CODING_STANDARDS.md`, so review agents fall back to generic smell heuristics. Audits found duplicated business rules, stale comments, incorrect ADR citations, and pages bypassing data-layer modules, with no written standard to cite.

**Environment improvement:** add concise, judgement-based standards: business rules have one domain owner; business logic cites its rule ID; ADR citations must support the claim; comments use current glossary terms; pages go through the data layer. Keep these as review guidance, not brittle mechanical rules where tooling is more appropriate.

### 7. Catch localization and RTL drift

The Storefront audit used ad hoc scripts to find missing translations and hard-coded English strings. The Dashboard lint configuration allows a large number of unpruned literal suppressions, and physical-direction CSS classes weaken RTL layout.

**Environment improvement:** add an architecture test that translation keys used in code exist and that English and Arabic key sets match. Ratchet hard-coded UI literals and physical-direction CSS toward zero, then remove permissive suppression handling as the backlog is resolved.

### 8. Add an ADR index and citation check

Finding the right decision required reading a large collection of ADRs. A spec also cited the wrong ADR for a business rule.

**Environment improvement:** add `docs/adr/README.md` with each ADR’s status, area, and decision summary. Add a check that ADR references resolve and flag citations to superseded decisions unless the replacement is also identified.

### 9. Check business-rule traceability

The business-gap audit manually searched for every CO-, SL-, PA-, and CA-prefixed rule. No code cites those rule IDs, so it is difficult to tell whether a rule is implemented, intentionally deferred, or missing.

**Environment improvement:** have business-rule code cite its rule ID and add a check that each documented rule is either referenced from code or explicitly marked as not implemented/deferred in the business docs.

### 10. Catch duplicated constants and cache-tag drift

The domain inventory found business constants duplicated across packages and backend code, including a Partner Report threshold with different application semantics. The Dashboard audit also found cache tag strings that did not match, so edits could leave stale lists.

**Environment improvement:** extend the domain value-copy check to cover duplicated exported business constants, and use shared entity cache-tag constants instead of string literals in cache invalidation calls.

### 11. Improve package and feature wayfinding

Some READMEs describe dead layers or point to missing examples; checkout has no feature README. Determining environment-variable loading and the actual feature boundaries required repeated searches.

**Environment improvement:** update stale package/app READMEs, add a checkout feature guide that points to the owners of its business rules, and document environment loading in the environment package README. Add a lightweight check for broken relative documentation links.

### 12. Reduce baseline work for read-only agents

The AGENTS.md branch instruction cost read-only agents an unnecessary tool call. The main session’s local `develop` was 22 commits behind `origin/develop`, so early findings were based on stale files until the branch was updated.

**Environment improvement:** scope the branch check to before the first commit. At session start, fetch or otherwise report when the current branch is behind its upstream before investigating checkout-specific claims.

### 13. Verify wired behavior through a smoke path

The audits mostly inferred runtime behavior from static code. That is useful for locating likely gaps but cannot confirm an entire customer or staff journey works.

**Environment improvement:** provide a repeatable smoke command that prepares a test database, starts the apps, and exercises selected journey URLs or API paths. Keep this separate from fast static architecture checks.

## Session-specific friction

- The source handoff contained claims that were already fixed or referred to dead code. Verify inherited claims against reachable code before making them acceptance criteria.
- The question about “test seams” was unclear to the user. Ask in plain terms which observable behavior should prove each workstream is correct.
- Four large audits ran in parallel and took several minutes. That was useful for broad coverage, but future audits should receive direct pointers to existing reports and a bounded output format before starting.

## Suggested order

1. Add the missing domain/business-doc pointers and zsh-safe shell note.
2. Add server-action authorization and `PermissionCode` enforcement.
3. Add app `server-only` and data-layer boundary checks.
4. Add unused-code/reachability checks and resolve their initial baseline.
5. Add localization, ADR-reference, and business-rule traceability checks.
6. Consolidate coding standards and repair stale wayfinding documentation.
7. Add the smoke path once the seeded app setup is stable.

Tickets #416, #418, and #424 already cover some domain-copy and data-layer work in the current issue plan. The rest of this retro is a set of environment improvements; it has not been implemented by this document commit.
